# Own To-dos Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** User-added to-dos (assignees, stop, due date) as the main list; the automatic to-dos as collapsed "Suggestions" that can be copied to the list.

**Architecture:** New `tasks` table with the same RLS as the other tables. Pure ordering logic lives in `src/domain/tasks.ts`. `TripData` gains `tasks`; `actions` gains task mutations. The To do tab and the stop page render them.

**Spec:** `docs/superpowers/specs/2026-11-21-own-todos-design.md`

## Global Constraints

- e2e only against local Supabase. The live migration push was consented by Daan on 2026-11-21 (`db push --remote --yes`, this migration only).
- Existing accessible names stay the same. The old suggestion buttons keep their text (the e2e tests click them after expanding).
- Today = the device's local date as `YYYY-MM-DD`.

## Review Focus

1. A suggestion's id changes when dates move, so "✓ on our list" can disappear after a reschedule. Accepted: the copied to-do itself stays.
2. Deleting a stop must keep its to-dos (`stop_id` set to null).
3. An empty to-do text is rejected in the UI and by the database `check`.

### Task 1: Schema

- [ ] Migration `supabase/migrations/<ts>_tasks.sql` creating table `tasks`:
  - `id uuid pk`, `trip_id` (FK cascade), `text` (`check length(trim(text)) > 0`), `done bool default false`, `done_at timestamptz`
  - `assignee_ids uuid[] default '{}'`, `stop_id` (FK set null), `due_date date`, `source_todo_id text`
  - `created_by default auth.uid()`, `created_at default now()`
  - RLS "members manage tasks" for authenticated; grants to authenticated; revoke anon; add to `supabase_realtime`
- [ ] Apply locally with `npx supabase migration up --local`. Add `tasks` to the `check-access.ts` TABLES list. Add a `Task` type in `types.ts`.

### Task 2: Domain

- [ ] Tests in `src/domain/tasks.test.ts` for `arrangeTasks(tasks: Task[], today: ISODate): { open: (Task & { overdue: boolean })[]; done: Task[] }`:
  - Open order: overdue first, then by due date with no date last, then by `created_at`.
  - Done order: newest `done_at` first.
  - Overdue means `due_date < today`.
  - Also `copiedTodoIds(tasks): Set<string>`.
- [ ] Implement, then commit.

### Task 3: Data and UI

- [ ] Write the e2e tests first in `e2e/tasks.e2e.ts`:
  - **Add with fields:** add "E2E Get visas" with an assignee, a stop and a due date. It appears under "Our list" with the stop tag. The To do tab count increases.
  - **Done:** ticking it moves it to "Done (1)" and the count decreases.
  - **Suggestions:** they're collapsed by default. "Suggestions" expands them, "Add to our list" copies the item, and the row then shows "✓ on our list".
  - **Stop page:** a to-do linked to a stop shows in that stop's "To-dos" section.
  - **Existing tests:** update the earlier to-do e2e tests so they expand Suggestions first.
- [ ] Provider: load `tasks`, sorted by `created_at`.
- [ ] Actions:
  - `addTask(input: { text; assignee_ids?; stop_id?; due_date?; source_todo_id? }): Promise<Task>`
  - `updateTask(id, patch)`: setting `done` also sets `done_at`
  - `deleteTask(id)`
- [ ] UI:
  - `TaskList` and `TaskForm` components
  - `TodoPanel` with "Our list", then a collapsed "Done (n)", then a collapsed "Suggestions (n)" whose open/closed state is kept in localStorage inside try/catch
  - the tab label is `To do (${open own count})`
  - `StopDetail` gets a "To-dos" section
- [ ] Run the full unit and e2e suites, screenshot the To do tab, then commit.

### Task 4: Deploy

- [ ] `npx supabase db push --remote --yes` (consented). Run check-access (including `tasks`), then merge, push, and watch the deploy. Read-only live check: the To do tab shows "Our list" and the Suggestions section is collapsed.
